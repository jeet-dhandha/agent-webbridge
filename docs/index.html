WebBridge — Real Chrome Browser Automation & MCP Server

WebBridge (also known as Agent WebBridge, Open WebBridge, or agent-webbridge) is an open-source (MIT), clean-room browser automation platform and Model Context Protocol (MCP) server that lets AI assistants (like Claude Code, Cursor, Windsurf) operate your real Google Chrome browser — with your existing logins and profiles — via the Chrome DevTools Protocol. Drives multiple profiles at once with true per-tab parallelism, community recipes (awb-recipes), and zero cloud dependencies (100% local on 127.0.0.1).

Architecture Comparison
Old Single Slot vs. Fleet Routing
The Single-Slot Limitation
Most browser bridges enforce a single connection slot and a single global "current tab", so they drive exactly one tab per profile at a time. Attempting to connect a second Chrome profile results in connection rejection.
Simultaneous Session Isolation
We spawn one isolated background daemon per Chrome profile on deterministic hashed ports. Each Google account profile runs fully isolated with independent cookies and storage.
Transparent Router Gateway
The proxy router serves as the central API gateway on port 10086. It accepts standard HTTP / MCP commands, extracts the "profile" parameter, and forwards the payload transparently to the corresponding daemon.

agent-webbridge is an open-source (MIT) browser automation engine and Model Context Protocol (MCP) server. It allows AI agents like Claude Code, Cursor, and Windsurf to drive your real Google Chrome — with your real login sessions — across multiple profiles simultaneously, with true per-tab parallel execution.
This is the killer feature. Most bridges funnel every CDP call through one global "current tab". agent-webbridge attaches the Chrome DevTools Protocol per tab (a Map keyed by tabId). 2, 5, and 10 tabs in a single profile evaluate concurrently in parallel: 5 tabs finish in ~3.5s flat versus 9.3s serially.
Run npm i -g agent-webbridge && awb setup "Work" once to install the extension and daemon. Then run claude mcp add chrome -- npx -y agent-webbridge mcp in Claude Code, or add the stdio command to your Cursor / Claude Desktop configuration file.
awb-recipes is a repository of community-maintained playbooks for automating complex websites (such as GitHub Gists, Google Search, Hacker News, LinkedIn, npm). Each recipe specifies verified steps, selector fallbacks, and anti-bot caveats in structured JSON, preventing agents from hallucinating broken selectors.

Because agent-webbridge runs a separate daemon for each profile behind a central router, commands directed at Gmail, Search Console, Ads, or Google Drive for different logins execute side-by-side without logging out.
agent-webbridge is published in the Official Model Context Protocol Registry (io.github.jeet-dhandha/agent-webbridge), featured on punkpeye/awesome-mcp-servers, listed in curated Awesome Claude Skills collections, installable via the Skills CLI (npx skills add jeet-dhandha/agent-webbridge), and published on npm and the Chrome Web Store.
Everything listens strictly on loopback 127.0.0.1 only. Starting in version 1.3.1, the router and daemons enforce strict Host and Origin validation, refusing any request carrying a web Origin or a non-loopback Host header. Websites you visit cannot drive the bridge.
